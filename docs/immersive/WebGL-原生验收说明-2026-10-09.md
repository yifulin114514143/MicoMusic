# WebGL 沉浸播放器原生验收

本轮验收使用本工作树的生产构建、生产 `PlayerControl` / `AudioController` 和生产插件加载、重载、卸载流程。Electron bundle 与 `userData` 仅位于 `artifacts/immersive-runtime/`，不读取或迁移已安装音乐客户端的账号资料。

## 证据位置与运行入口

- 运行：`node scripts/run-immersive-validation.mjs`，前置条件为本工作树已执行生产构建。
- 新证据：`docs/immersive/evidence/webgl/validation.json` 与 `validation-unthrottled.json`。
- 动态证据：同目录 `11-webgl-motion.mp4` 与 `11-webgl-motion-unthrottled.mp4`，由 Electron `capturePage` 的连续真实帧编码。
- 封面交叠证据：同目录 `13-glass-cover-overlap.png` 与其 unthrottled 版本。
- 失败证据：`failed-attempts/` 中保留每次失败报告、日志与截图，修复后重跑不覆盖失败记录。
- 原 `docs/immersive/evidence/validation*.json` 为 2026-10-08 的 CSS 版本记录，不能用来证明本轮 WebGL 工作树已通过。

## 观察方法

生产插件位于 Chrome extension 的 `ISOLATED` world，主世界的 WebGL wrapper 无法观察它。本轮通过实际插件弹窗的 `chrome.scripting.executeScript` 在同一隔离世界安装原生调用观察器；观察器保留 WebGL、RAF、监听器、观察器的原生行为及返回值。主世界独立观察实际 Audio 与歌词 DOM。

背景流动读取实际 GL 绘制后复制到可见背景输出的 2D 像素；玻璃读取自然绘制完成后的 GL framebuffer 与透明玻璃输出。读回不主动重画、不改变 shader uniforms，不以 CSS 动画状态代替实际像素变化。两者采用同一 GL context 和两张 2D 输出画布。

验收包含：shader 编译与链接、真实 SVG 封面提色及场景纹理上传、播放时像素变化、暂停时菜单玻璃差分、菜单与封面交叠及按钮可交互、真实上下文 loss/restore、Hero 入退场与中途退出连续性、菜单中途反转、实际音频驱动逐词填充、ODE 歌词跟随、20 次材质关闭启用、3 次生产 IPC 重载、窗口隐藏与最小化、低模糊与减少动效、实际生产 IPC 卸载后的旧界面回退。资源检查同时包括 GL 对象、RAF 和三个自有 canvas 的撤除。

## 首轮意外暂停的独立记录

最早失败证据位于 `evidence/webgl/failed-attempts/2026-10-09T03-16-37-497Z-default/`。当时实际 Audio 停在 1.314635 秒，`paused=true`、`data-motion=still`，两次背景像素读回相同。断言准确发现了停止播放，不能将它改写成流体已通过，也不能用后续重跑通过证明这个暂停已经修复。用户对当时是否操作暂停回答“不记得”，不将其视为确认有人为操作。

已核查首轮的精确操作与源码：Tab / Shift+Tab 和 (8,8) 空边原生点击均在开始播放前；播放通过实际 DOM 播放按钮触发；播放后至失败仅执行指针移到空边、只读几何、时间等待和像素读回，没有再点暂停或发送 Space。请求记录中没有 `/song/url` 或第二首音频请求，时长为 180 秒，队列未切换。输出设备变化自动暂停的源码默认值为 `off`，技术 fixture 没有启用该设置。MediaSession 注册了实际处理函数，但首轮没有保存其触发记录。

首轮只记录警告级控制台信息，未记录原生输入事件与 `pause()` 调用栈，故无法追溯到具体触发源。后续已增加真实事件目标与可信标志、测试动作日志、全部控制台信息、原生 `pause()` 调用栈；若暂停重现，会随失败状态保存。后续同初始操作流程没有复现 1.314635 秒暂停；保留的后续失败状态中，最早 `pause()` 调用栈对应测试主动进行玻璃差分的 DOM 暂停按钮。结论仍为：首轮触发源未定位，没有据此修改生产音频逻辑。
